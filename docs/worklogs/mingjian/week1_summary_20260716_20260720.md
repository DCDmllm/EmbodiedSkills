本周完成了 CALVIN 工程线从 Stage 0 到 Stage 4 开发矩阵的闭环：建立独立运行环境与测试门禁，打通真实 CALVIN reset/capture、X-VLA `/act`、`env.step()` 和 task oracle，跑通单任务完整 Agent，并实现可断点续跑的五步序列评测器。固定 10 序列开发矩阵中，X-VLA baseline 与 ClawVLA Agent 均为 `7/10` 完整成功、平均完成 `3.9/5`，没有环境或 HTTP 异常。

## 小规模失败归因

对主矩阵共同失败的 `official_001`、`official_008`、`official_009` 进行 planner-free X-VLA 诊断：

|实验|`001`|`008`|`009`|
|---|---:|---:|---:|
|原协议复跑，120 步/子任务|0/5|3/5|1/5|
|诊断预算，240 步/子任务|5/5|5/5|1/5|

原协议复跑完全重现主矩阵失败且无系统异常。增加预算后，`001` 的 LED 任务在 182 步成功，`008` 的 slider block lift 在 108 步成功；`009` 的 blue block lift 到 240 步仍失败，末帧和 oracle 均显示没有完成抬起。因此两条失败含预算/轨迹波动因素，一条是稳定低层能力或恢复缺口。诊断结果不替换固定协议的 `7/10` 主结果。

## 本周发现并固化的关键问题

|问题|影响|处理|
|---|---|---|
|localhost 请求被系统代理转发|PolicyProxy/X-VLA 出现 502|所有本地服务命令显式设置 `NO_PROXY` 和 `no_proxy`|
|X-VLA `steps` 被误当成动作行数|正常 30 行响应可能被错误拒绝|记录原始响应形状并有界消费动作前缀|
|close 后保留 episode 动态状态|跨 episode 污染|清理 observation、reward、done、info 和 step count|
|direct VLA 被候选框 preflight 阻塞|CALVIN 无法进入动作执行|backend 声明无需 candidate bindings|
|Planner JSON 截断反复 stall|五步序列在原子任务处卡死|解析失败时按 backend contract 生成官方原子子目标|
|Verifier 在 oracle false 时结束|产生 premature finish|oracle 成为唯一终局权威并恢复当前子目标|
|官方序列池随请求 N 漂移|同一 index 对应不同序列|固定 1000 pool 并在运行前校验 manifest|
